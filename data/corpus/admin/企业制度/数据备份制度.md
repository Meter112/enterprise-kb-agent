# 数据备份制度

## 备份范围

本制度适用于云帆科技及其控股子公司全部信息系统、数据资产与备份介质管理，覆盖研发、生产、办公、财务、客户服务等业务场景。数据按重要程度分为A、B、C三级：A类为核心数据，包括生产数据库（订单、支付、用户身份、结算、风控）、源代码仓库、密钥与证书、核心配置及审计日志，一旦丢失或篡改，单次直接经济损失可能超过人民币500万元，并可能触发监管报告；B类为重要数据，包括CRM、ERP、OA、邮件、工单、财务凭证影像、监控指标等，丢失可能影响业务连续性，单次损失预估50万至500万元；C类为一般数据，包括测试数据、临时文件、培训资料、已公开文档等，丢失影响较小。A类数据必须执行本地、异地、离线归档相结合的3-2-1-1原则，B类至少本地与异地各一份，C类可仅本地或低成本对象存储。所有备份须加密存储，A类采用AES-256，传输采用TLS 1.3；备份介质、云存储桶和恢复账号由信息安全部统一登记，任何部门不得私建备份通道。外包或云服务商需签署数据保护条款，若涉及A类数据，须通过年度安全评估，评估得分不低于85分。

## 备份频率

各系统责任人应在变更后2个工作日内更新备份策略。备份任务统一在低峰窗口执行，A类数据库全量备份每日02:00启动，增量或日志备份每15分钟一次；B类系统每日或每周执行全量，并辅以差异备份；C类数据每周日03:00全量备份。备份保留周期遵循合规与成本平衡：A类本地保留30天、异地保留180天、离线归档保留3年；B类本地14天、异地90天；C类本地7天、异地30天。备份成功率目标不低于99.5%，失败任务须在30分钟内触发企业微信与短信告警，责任人在2小时内响应、4小时内修复或重跑。年度备份专项预算不超过人民币80万元，其中异地存储与加密服务占比不低于40%。备份频率对照表如下：

| 数据类别 | 典型系统/数据 | 备份方式 | 备份频率 | 保留周期 | RPO | RTO |
|---|---|---|---|---|---|---|
| A类核心数据 | 生产数据库、订单、支付、用户身份、密钥、源码仓库 | 全量+增量+实时日志，本地+异地+离线归档 | 全量每日02:00；增量每15分钟；日志实时 | 本地30天，异地180天，归档3年 | ≤15分钟 | ≤2小时 |
| B类重要数据 | CRM、ERP、OA、邮件、工单、财务影像 | 全量+差异，本地+异地 | 全量每周日01:00；差异每日01:30 | 本地14天，异地90天 | ≤24小时 | ≤8小时 |
| C类一般数据 | 测试数据、临时文件、培训资料 | 全量，本地或对象存储 | 每周日03:00 | 本地7天，异地30天 | ≤7天 | ≤24小时 |
| 代码与配置 | Git仓库、CI/CD配置、网络策略 | 实时同步+每日快照 | 实时；快照每日04:00 | 快照保留180天，发布版本保留3年 | ≤5分钟 | ≤1小时 |
| 虚拟机与容器镜像 | 核心业务虚机、镜像仓库 | 全量+增量 | 全量每周六23:00；增量每日23:30 | 30天 | ≤24小时 | ≤4小时 |

注：RPO为恢复点目标，RTO为恢复时间目标；表中时限为业务可接受上限，实际恢复应以演练结果为准。财务、法务等有专项监管要求的数据，保留周期从其规定，但不得低于本表下限。

## 恢复演练

恢复演练由信息安全部牵头，各系统责任人、运维团队和业务代表共同参与。A类核心系统每季度至少演练1次，B类重要系统每半年至少1次，C类一般系统每年至少1次；新系统上线前、重大架构变更后、备份介质或云服务商切换后，必须完成一次专项恢复演练。年度演练覆盖率应达到100%，A类系统恢复成功率不低于98%，B类不低于95%。演练场景包括误删除、勒索软件加密、机房断电、区域网络中断、云存储桶误配置等。演练须在隔离环境进行，严禁直接覆盖生产数据；如需生产环境验证，须经CTO审批并选择业务低峰期，且提前30分钟通知相关业务方。

演练流程包括：提交演练申请、风险评估、审批、环境准备、数据恢复、完整性校验、业务验证、回滚与清理、形成报告。完整性校验至少包括记录数、关键金额合计、文件哈希和抽样业务查询；业务验证由业务代表确认订单、支付、客户等核心流程可读可用。演练结束后5个工作日内提交《恢复演练报告》，问题整改原则上在10个工作日内闭环；若A类系统恢复失败或RTO超出2小时，应在24小时内上报CTO，并在3个工作日内提交专项整改方案。以下为恢复验证脚本示例：

```bash
#!/bin/bash
# 云帆科技核心数据库恢复验证脚本（仅限演练环境）
set -euo pipefail
BACKUP_FILE="/backup/mysql/full_2025-06-01.sql.gz"
TARGET_DB="verify_core"
RESTORE_HOST="10.20.1.30"
RESTORE_USER="restore_user"

mysql -h "${RESTORE_HOST}" -u "${RESTORE_USER}" -p"${RESTORE_PWD}" \
  -e "DROP DATABASE IF EXISTS ${TARGET_DB}; CREATE DATABASE ${TARGET_DB};"

zcat "${BACKUP_FILE}" | mysql -h "${RESTORE_HOST}" -u "${RESTORE_USER}" -p"${RESTORE_PWD}" "${TARGET_DB}"

ORDER_COUNT=$(mysql -h "${RESTORE_HOST}" -u "${RESTORE_USER}" -p"${RESTORE_PWD}" \
  -N -B -e "SELECT COUNT(*) FROM ${TARGET_DB}.orders;")

if [ "${ORDER_COUNT}" -lt 100000 ]; then
  echo "恢复校验失败：订单记录数 ${ORDER_COUNT} 低于 100000" >&2
  exit 1
fi

echo "恢复校验通过：订单记录数 ${ORDER_COUNT}，时间 $(date '+%F %T')"
```

本制度自发布之日起执行，由信息安全部负责解释和修订，每年至少评审一次；违反本制度导致数据丢失、泄露或业务中断的，按公司信息安全奖惩规定追究责任。
