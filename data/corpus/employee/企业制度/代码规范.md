# 代码规范

为统一云帆科技代码资产风格，降低维护成本，提升协作与交付效率，特制定本规范。本规范适用于公司各研发团队、外包合作方及内部工具开发，自发布之日起执行，由研发效能部负责解释与修订，每半年复盘一次。

## 命名规范

代码命名应做到见名知意、长度适中、避免歧义，Python 代码须遵循 PEP 8。禁止使用拼音、无意义缩写及单字符命名，循环变量 `i`、`j`、`k` 除外。变量、函数命名长度建议为 3—30 个字符，类名为 3—40 个字符，常量为 3—50 个字符。布尔变量须以 `is_`、`has_`、`can_`、`should_` 开头。

| 类型 | 规则 | 正例 | 反例 |
| --- | --- | --- | --- |
| 变量/函数 | 小写蛇形命名，语义完整 | `calculate_total_amount` | `calcAmt`、`jine` |
| 类/异常 | 大驼峰命名，名词或名词短语 | `OrderItem`、`PaymentError` | `order_item`、`PayErr` |
| 常量 | 全大写蛇形命名 | `MAX_RETRY_COUNT` | `maxRetry` |
| 模块/包 | 小写蛇形命名，简短明确 | `order_service` | `OrderService`、`os2` |
| 私有成员 | 单下划线前缀 | `_validate_token` | `validateToken` |
| 布尔变量 | 使用 `is_/has_/can_/should_` 前缀 | `is_paid`、`has_permission` | `paid_flag`、`auth` |

命名不得使用公司敏感项目代号、客户名称或个人信息。涉及金额、税率、折扣等字段时，须在名称中体现单位或精度，例如 `amount_cent`、`rate_percent`、`unit_price_decimal`。

## 提交规范

代码提交须遵循 Conventional Commits 格式：`<type>(<scope>): <subject>`。标题不超过 50 个字符，正文每行不超过 72 个字符。一个提交只完成一件事，单次有效变更建议不超过 300 行；超过 500 行须拆分提交，紧急热修复可事后 1 个工作日内补充说明。提交信息须关联需求或缺陷编号，格式为 `YF-YYYY-NNN`。

| 类型 | 用途 | 示例 |
| --- | --- | --- |
| feat | 新增功能 | `feat(order): 支持优惠券抵扣` |
| fix | 修复缺陷 | `fix(payment): 修复退款金额取整错误` |
| docs | 文档变更 | `docs(readme): 补充本地启动说明` |
| refactor | 重构且不改变行为 | `refactor(user): 拆分用户校验逻辑` |
| perf | 性能优化 | `perf(query): 增加订单索引命中` |
| test | 测试相关 | `test(order): 补充金额边界用例` |
| chore | 构建、依赖、工具 | `chore(ci): 升级单元测试镜像` |

功能分支须至少每日提交 1 次；开发完成后 1 个工作日内发起合并请求。提交前必须本地运行单元测试与静态检查，新增代码单元测试覆盖率不低于 80%，存量模块覆盖率不低于 60%。CI 通过率应保持 100%，未通过不得申请人工评审。

## 评审流程

代码评审实行“自动检查 + 人工评审 + 修改闭环 + 合并入库”流程。每个合并请求至少 1 名评审人；支付、权限、核心账务模块须 2 名评审人，其中至少 1 名为高级工程师。评审人须在 4 小时内响应，24 小时内完成首次评审。严重问题须 2 小时内修复，普通问题 1 个工作日内修复，建议类问题 3 个工作日内答复。单次评审有效变更超过 400 行时，评审人有权要求拆分；超过 800 行必须拆分。

| 阶段 | 责任人 | 时限 | 输出 |
| --- | --- | --- | --- |
| 发起评审 | 提交人 | 开发完成后 1 个工作日内 | MR 链接、需求编号、自测说明 |
| 自动检查 | CI 系统 | 10 分钟内 | 构建、单测、静态扫描结果 |
| 人工评审 | 评审人 | 4 小时内响应，24 小时内完成 | 评审意见、Approve 或 Request Changes |
| 修改闭环 | 提交人 | 严重 2 小时，普通 1 个工作日 | 修改提交、评论回复 |
| 合并入库 | 提交人或评审人 | 通过后 4 小时内 | 合并记录、发布说明 |

评审目标：一次评审通过率不低于 70%，评审超时率不高于 5%，严重缺陷逃逸率不高于 0.5%。季度优秀评审人奖励 500 元，优秀代码质量团队奖励 2000 元。因未按规范提交或评审导致生产事故的，按公司《质量奖惩办法》处理；直接经济损失超过 5000 元的，提交质量委员会审议。

## 示例

以下 Python 示例展示命名、类型注解、常量、异常处理及金额计算方式。金额统一使用 `Decimal`，并保留两位小数。

```python
from dataclasses import dataclass
from decimal import Decimal
from typing import Iterable

MAX_RETRY_COUNT = 3
DEFAULT_TIMEOUT_SECONDS = 30
AMOUNT_QUANTIZE = Decimal("0.01")


@dataclass(frozen=True)
class OrderItem:
    sku: str
    quantity: int
    unit_price: Decimal


def calculate_total_amount(items: Iterable[OrderItem]) -> Decimal:
    """计算订单总金额，金额使用 Decimal，避免浮点误差。"""
    total = Decimal("0.00")
    for item in items:
        if item.quantity <= 0:
            raise ValueError("商品数量必须大于 0")
        if item.unit_price < Decimal("0.00"):
            raise ValueError("商品单价不能为负数")
        total += item.unit_price * item.quantity
    return total.quantize(AMOUNT_QUANTIZE)


def main() -> None:
    items = [
        OrderItem(sku="YF-1001", quantity=2, unit_price=Decimal("39.90")),
        OrderItem(sku="YF-1002", quantity=1, unit_price=Decimal("129.00")),
    ]
    total_amount = calculate_total_amount(items)
    print(f"订单总金额：{total_amount} 元")


if __name__ == "__main__":
    main()
```
